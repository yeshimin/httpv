# Security policy

## Supported versions

Security fixes are provided for the latest released minor version. Until the
first tagged release, only the current default branch is supported.

## Reporting a vulnerability

Do not open a public issue for authentication bypasses, request-data exposure,
remote code execution, proxy routing bypasses, or other vulnerabilities.
Instead, use GitHub's **Report a vulnerability** flow to create a private
security advisory for this repository. Include affected versions, deployment
mode, reproduction steps, impact, and any proposed mitigation.

The project will acknowledge a complete report, validate it privately, prepare
a fix and regression test, and coordinate disclosure after a patched release is
available. Never include real credentials, cookies, captured bodies, or customer
traffic in a report; use synthetic data.
